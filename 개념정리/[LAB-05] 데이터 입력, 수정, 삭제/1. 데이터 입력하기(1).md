# 데이터 입력, 수정, 삭제

테이블에 데이터를 새로 추가하거나 기존 데이터를 수정·삭제할 때는 각각 `INSERT`, `UPDATE`, `DELETE` 문을 사용한다.

이번 내용에서는 먼저 `INSERT` 문을 사용하여 테이블에 데이터를 입력하는 방법과 데이터 무결성을 위한 주요 제약조건을 알아본다.

---

# 데이터 입력

`INSERT` 문은 테이블에 **새로운 행(Row)을 추가**할 때 사용하는 명령어이다.

### 기본 형식

```sql
INSERT INTO 테이블명 (필드1, 필드2, ...)
VALUES (값1, 값2, ...);
```

- `INSERT INTO` : 데이터를 추가할 테이블을 지정
- `(필드1, 필드2, ...)` : 값을 입력할 필드를 지정
- `VALUES` : 실제로 저장할 값을 지정
- 필드와 값의 **개수와 순서가 서로 일치**해야 한다.

---

## 필드명을 생략하는 경우

테이블의 모든 필드에 값을 입력한다면 필드명을 생략할 수 있다.

```sql
INSERT INTO departments
VALUES (
    500,
    '인공지능학과',
    '공학관',
    '051-123-4567',
    'ai@myschool.ac.kr',
    2001,
    'http://ai.myschool.ac.kr'
);
```

필드명을 생략하면 테이블에 정의된 **필드 순서대로 모든 값을 입력**해야 한다.

테이블의 구조와 필드 순서는 `DESC`를 사용하여 확인할 수 있다.

```sql
DESC departments;
```

---

## 필드명을 지정하는 경우

입력할 필드명을 직접 지정할 수도 있다.

```sql
INSERT INTO departments (
    id,
    dname,
    loc,
    phone,
    email,
    established,
    homepage
)
VALUES (
    501,
    '사회복지학과',
    '인문관',
    '051-432-2233',
    'social@myschool.ac.kr',
    2002,
    'http://social.myschool.ac.kr'
);
```

필드명을 지정하면 테이블에 정의된 원래 필드 순서와 다르게 작성할 수 있다.

단, 지정한 필드와 `VALUES`에 작성한 값은 서로 순서가 일치해야 한다.

```text
(id, dname, loc)
 ↓     ↓     ↓
(501, '사회복지학과', '인문관')
```

---

# 데이터 무결성

데이터 무결성(Data Integrity)은 데이터베이스에 저장되는 데이터의 **정확성과 일관성을 유지하는 것**을 의미한다.

잘못되거나 유효하지 않은 데이터가 저장되는 것을 방지하기 위해 여러 가지 제약조건을 사용한다.

| 구분 | 의미 | 관련 제약조건 |
|---|---|---|
| 엔티티 무결성 | 각각의 행을 고유하게 식별 | `PRIMARY KEY` |
| 도메인 무결성 | 필드에 허용되는 값의 범위를 제한 | 데이터 타입, `NOT NULL` |
| 참조 무결성 | 테이블 간의 올바른 참조 관계 유지 | `FOREIGN KEY` |

---

## 엔티티 무결성

엔티티 무결성은 테이블의 각 행을 **유일하게 식별할 수 있어야 한다는 규칙**이다.

주로 `PRIMARY KEY`를 사용하여 보장한다.

```text
PRIMARY KEY
→ 중복된 값 사용 불가
→ NULL 사용 불가
→ 각각의 행을 고유하게 식별
```

---

## 도메인 무결성

도메인 무결성은 각 필드에 **허용된 범위와 형식의 값만 저장되도록 하는 규칙**이다.

데이터 타입이나 `NOT NULL` 등의 제약조건을 사용한다.

```text
나이 → 숫자 데이터
이름 → NULL 허용 여부 설정
날짜 → 날짜 형식의 데이터
```

---

## 참조 무결성

참조 무결성은 다른 테이블의 데이터를 참조할 때 **실제로 존재하는 데이터만 참조하도록 하는 규칙**이다.

주로 `FOREIGN KEY`를 사용한다.

```text
students.department_id
        ↓
departments.id
```

학생의 학과 번호는 `departments` 테이블에 존재하는 학과 번호를 참조해야 한다.

---

# PRIMARY KEY

`PRIMARY KEY`는 테이블의 각 행을 **고유하게 식별하기 위한 기본키**이다.

테이블 구조를 확인하면 `Key` 항목의 `PRI`를 통해 기본키를 확인할 수 있다.

```sql
DESC departments;
```

```text
Field   Null   Key
id      NO     PRI
```

`PRIMARY KEY`는 다음과 같은 특징을 가진다.

- 중복된 값을 가질 수 없다.
- `NULL` 값을 가질 수 없다.
- 하나 이상의 필드로 구성할 수 있다.
- 하나의 테이블에는 하나의 `PRIMARY KEY`만 존재한다.

---

## PRIMARY KEY의 중복

이미 존재하는 기본키 값을 다시 입력하면 오류가 발생한다.

예를 들어 `id`가 `501`인 데이터가 이미 존재하는 상태에서 같은 값을 다시 입력하면 다음과 같은 오류가 발생한다.

```text
ERROR 1062 (23000): Duplicate entry '501' for key 'PRIMARY'
```

즉, 기본키를 통해 각각의 행이 서로 다른 값을 갖도록 보장할 수 있다.

```text
PRIMARY KEY
→ 중복 불가
→ NULL 불가
```

---

# AUTO_INCREMENT

`AUTO_INCREMENT`는 새로운 데이터가 입력될 때 **숫자 값을 자동으로 증가시켜 저장하는 속성**이다.

주로 `PRIMARY KEY`와 함께 일련번호를 생성할 때 사용한다.

```sql
DESC departments;
```

`AUTO_INCREMENT`가 설정된 필드는 `Extra` 항목에서 확인할 수 있다.

```text
Field   Key   Extra
id      PRI   auto_increment
```

기존의 마지막 번호가 `501`이라면 다음 데이터를 추가할 때 자동으로 `502`가 생성된다.

---

## NULL을 사용한 자동 증가

`AUTO_INCREMENT`가 설정된 필드에 `NULL`을 입력하면 다음 번호가 자동으로 생성된다.

```sql
INSERT INTO departments
VALUES (
    NULL,
    '심리학과',
    '인문관',
    '051-336-7788',
    'psyc@myschool.ac.kr',
    2000,
    'http://psyc.myschool.ac.kr'
);
```

이때 `id`에 실제로 `NULL`이 저장되는 것이 아니라 **자동으로 증가한 번호가 저장**된다.

---

## 자동 증가 필드 생략

필드명을 직접 지정하는 경우 `AUTO_INCREMENT` 필드를 아예 생략할 수도 있다.

```sql
INSERT INTO departments (
    dname,
    loc,
    phone,
    email,
    established,
    homepage
)
VALUES (
    '체육학과',
    '체육관',
    '051-434-3345',
    'phy@myschool.ac.kr',
    2004,
    'http://phy.myschool.ac.kr'
);
```

`id`를 입력하지 않았지만 `AUTO_INCREMENT`에 의해 다음 번호가 자동으로 생성된다.

```text
AUTO_INCREMENT

NULL 입력
→ 자동으로 다음 번호 생성

필드 생략
→ 자동으로 다음 번호 생성
```

---

# NULL

`NULL`은 **값이 존재하지 않는 상태**를 의미한다.

숫자 `0`이나 빈 문자열 `''`과는 의미가 다르다.

```text
NULL
→ 값이 없음

0
→ 숫자 0이라는 값이 있음

''
→ 길이가 0인 문자열 값이 있음
```

---

## NULL 직접 입력

`NULL`을 허용하는 필드에는 직접 `NULL`을 입력할 수 있다.

```sql
INSERT INTO departments (
    dname,
    loc,
    phone,
    email,
    established,
    homepage
)
VALUES (
    '성악과',
    '음악관',
    '051-435-3535',
    'music@myschool.ac.kr',
    2004,
    NULL
);
```

이 경우 `homepage`에는 값이 없는 상태인 `NULL`이 저장된다.

---

## 필드를 생략하여 NULL 입력

`NULL`을 허용하는 필드는 `INSERT` 문에서 생략할 수도 있다.

```sql
INSERT INTO departments (
    dname,
    loc,
    phone,
    email,
    established
)
VALUES (
    '정보통신학과',
    '공학관',
    '051-436-3636',
    'ic@myschool.ac.kr',
    2004
);
```

`homepage` 필드를 생략했으므로 해당 필드에는 `NULL`이 저장된다.

단, 해당 필드가 `NULL`을 허용해야 한다.

---

# NOT NULL

`NOT NULL`은 특정 필드에 **반드시 값이 입력되도록 제한하는 제약조건**이다.

테이블 구조의 `Null` 항목을 통해 `NULL` 허용 여부를 확인할 수 있다.

```sql
DESC departments;
```

```text
Null : NO
→ NULL 허용 안 함

Null : YES
→ NULL 허용
```

---

## NOT NULL 필드에 NULL 입력

`NOT NULL`이 설정된 필드에는 `NULL`을 입력할 수 없다.

예를 들어 `phone`이 `NOT NULL`인 경우 다음과 같이 입력하면 오류가 발생한다.

```sql
INSERT INTO departments (
    dname,
    loc,
    phone,
    email,
    established,
    homepage
)
VALUES (
    '고고학과',
    '인문관',
    NULL,
    'music@myschool.ac.kr',
    2005,
    NULL
);
```

---

## NOT NULL 필드 생략

기본값이 없는 `NOT NULL` 필드를 `INSERT` 문에서 생략해도 오류가 발생한다.

```text
ERROR 1364 (HY000): Field 'phone' doesn't have a default value
```

따라서 `NOT NULL`로 지정된 필드는 반드시 값을 입력해야 한다.

---

# 핵심 정리

```text
INSERT
→ 테이블에 새로운 행을 추가
→ 필드와 값의 개수 및 순서가 일치해야 함

필드명 생략
→ 모든 필드의 값을 테이블 순서대로 입력

필드명 지정
→ 필요한 필드만 선택하여 입력 가능

데이터 무결성
→ 데이터의 정확성과 일관성을 유지

PRIMARY KEY
→ 각 행을 고유하게 식별
→ 중복 불가
→ NULL 불가

AUTO_INCREMENT
→ 새로운 데이터가 추가될 때 번호를 자동 생성
→ NULL을 입력하거나 필드를 생략할 수 있음

NULL
→ 값이 존재하지 않는 상태
→ 0이나 빈 문자열과 다름

NOT NULL
→ 반드시 값이 존재해야 함
→ NULL 입력 불가
```

VALUES (값1, 값2, ...);

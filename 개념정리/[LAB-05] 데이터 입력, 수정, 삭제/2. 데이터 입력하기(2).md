# 데이터 입력하기 (2)

## 데이터 타입에 의한 도메인 무결성

각각의 컬럼은 정해진 형식의 데이터만 저장 가능함

이를 통해 가장 기본적인 **도메인 무결성**을 보장할 수 있음

### ENUM(A, B, C ...) 타입

괄호 안에 나열된 값들 중 하나만 저장할 수 있는 형태로 좀 더 강력한 **도메인 무결성**을 보장함

```sql
DESC professors;
```

`professors` 테이블의 `position` 컬럼은 다음과 같이 `ENUM` 타입으로 지정되어 있다.

```text
enum('교수','부교수','조교수','전임강사')
```

따라서 지정된 값 이외의 값을 저장할 수 없다.

예를 들어 `position`에 `석좌교수`를 저장하면 도메인 무결성 제약조건 위반으로 에러가 발생한다.

```sql
INSERT INTO professors (
    name, user_id, position, sal, hiredate, status, department_id
) VALUES (
    '홍석민', 'hong', '석좌교수', 580, '2020-11-09', '재직', 101
);
```

```text
ERROR 1265 (01000): Data truncated for column 'position' at row 1
```

# 참조키(FOREIGN KEY)에 대한 이해

교수의 소속 학과를 확인하기 위해서는 교수 테이블의 소속 학과 번호와 학과 테이블의 학과 번호를 연결해서 확인해야 한다.

교수 테이블에 저장되는 `department_id`가 학과 테이블에 저장되어 있는 `id`와 일치하지 않는 경우 논리적으로 맞지 않게 된다.

이를 **참조키**에 위배된다고 표현한다.

즉 교수 테이블의 `department_id`는 학과 테이블의 `id`를 **참조**하는 값이어야 한다.

## FOREIGN KEY

한 테이블의 컬럼(Column)이 다른 테이블의 **기본키**를 참조하는 키

테이블 간의 **관계**를 나타내기 위해 사용됨

테이블 간 관계를 통해 데이터 구조를 논리적으로 표현한다.

### 참조 무결성(Referential Integrity) 유지

존재하지 않는 데이터를 참조하지 않도록 방지한다.

학과 테이블에 없는 `id`를 교수 테이블에 저장할 경우 에러가 발생한다.

## 테이블 구조에서 참조키 확인하기

참조키는 테이블 구조의 Key 필드에 `MUL`로 표시된다.

```sql
DESC professors;
```

```text
department_id | int(11) | NO | MUL | NULL |
```

이는 교수 테이블의 `department_id` 컬럼이 다른 테이블을 참조하는 자식 데이터의 역할을 하고 있음을 의미한다.

## myschool 데이터베이스의 참조키 관계

| 자식 테이블 | 참조키 컬럼 | 부모 테이블 | 부모 테이블의 기본키 |
|---|---|---|---|
| enrollments | student_id | students | id |
| enrollments | subject_id | subjects | id |
| professors | department_id | departments | id |
| students | department_id | departments | id |
| students | professor_id | professors | id |
| subjects | department_id | departments | id |
| subjects | professor_id | professors | id |

# 참조키에 데이터 저장하기

컴퓨터공학과(101)에 김기봉 교수의 정보를 저장한다.

```sql
INSERT INTO professors (
    name, user_id, position, sal, hiredate, comm,
    email, phone, photo_url, status, department_id
) VALUES (
    '김기봉', 'kibong', '교수', 480, '2021-10-05', 50,
    'kibong@myschool.ac.kr', '010-9988-7766', NULL, '재직', 101
);
```

참조키인 `department_id`에 `101`을 저장할 수 있는 이유는 `departments` 테이블에 `id = 101`인 학과가 존재하기 때문이다.

## 존재하지 않는 참조값 저장

존재하지 않는 학과 번호를 저장하는 경우 에러가 발생한다.

```sql
INSERT INTO professors (
    name, user_id, position, sal, hiredate, comm,
    email, phone, photo_url, status, department_id
) VALUES (
    '김기봉', 'kibong', '교수', 480, '2021-10-05', 50,
    'kibong@myschool.ac.kr', '010-9988-7766', NULL, '재직', 9999
);
```

```text
ERROR 1452 (23000): Cannot add or update a child row: a foreign key constraint fails
```

`departments` 테이블에 존재하지 않는 학과 번호 `9999`를 참조하려 했기 때문에 참조 무결성 제약조건을 위반한다.

# 암호화 된 값을 저장하기

`students` 테이블에 101번 학과에 재학중인 학생 한 명을 등록하되, 주민등록번호는 실제 번호 대신 MD5 해시 함수를 사용하여 저장한다.

```sql
INSERT INTO students (
    name, user_id, grade, idnum, birthdate, gender,
    phone, height, weight, status, department_id
) VALUES (
    '김태영', 'kimty', 1, MD5('060517-4123456'), '2006-05-17', '남',
    '010-9877-6654', 175, 98, '재학', 101
);
```

## MD5(x)

`x`를 암호화한 값을 저장한다.

암호화 결과는 영문 소문자와 16진수를 조합한 32글자로 생성된다.

암호화된 값은 다시 복호화가 불가능하기 때문에 검색 조건으로 사용해야 할 경우 저장한 값과 암호화 함수의 적용 결과를 비교해야 한다.

```sql
SELECT name, user_id, grade, idnum
FROM students
WHERE user_id='kimty'
  AND idnum=MD5('060517-4123456');
```

# 현재 시각을 저장하기

101번 학과에 현재 시각을 입사일로 설정하여 김도현 교수의 정보를 추가한다.

특정 시각을 저장할 경우 `'YYYY-MM-DD HH:MI:SS'` 형식 혹은 `'YYYY-MM-DD'` 형식의 문자열로 저장한다.

현재 시각을 저장할 때는 `NOW()` 함수를 사용할 수 있다.

```sql
INSERT INTO professors (
    name, user_id, position, sal, hiredate, status, department_id
) VALUES (
    '김도현', 'dhkim', '교수', 580, NOW(), '재직', 101
);
```

# 핵심 정리

```text
도메인 무결성
→ 컬럼에 정의된 데이터 타입과 범위에 맞는 값만 저장

ENUM
→ 미리 정의된 값 중 하나만 저장 가능
→ 허용되지 않은 값을 저장하면 오류 발생

FOREIGN KEY
→ 다른 테이블의 기본키를 참조하는 키
→ 테이블 간의 관계를 표현

참조 무결성
→ 존재하지 않는 데이터를 참조하지 못하도록 제한

MUL
→ 중복 가능한 인덱스를 의미
→ 외래키 컬럼에서 자주 확인할 수 있음

MD5()
→ 입력값을 해시값으로 변환하여 저장

NOW()
→ 현재 날짜와 시간을 반환
```

## 기본 구조

```sql
컬럼명 ENUM('값1', '값2', '값3')

-- MD5
MD5('값')

-- 현재 시각
NOW()
```

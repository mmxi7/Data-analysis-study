# LAB 05. 데이터 입력, 수정, 삭제

## 1. 데이터 입력하기

### 1-1. INSERT 문

테이블에 새로운 데이터를 추가할 때 `INSERT INTO` 문을 사용한다.

```sql
INSERT INTO 테이블명 (컬럼1, 컬럼2, ...)
VALUES (값1, 값2, ...);
```

- `INSERT INTO` : 새로운 데이터를 테이블에 추가
- `테이블명` : 데이터를 저장할 테이블
- `(컬럼1, 컬럼2, ...)` : 데이터를 저장할 컬럼
- `VALUES` : 실제 저장할 값
- 컬럼과 값의 **개수와 순서가 일치**해야 한다.
- 문자와 날짜는 작은따옴표(`' '`)로 감싼다.
- 숫자는 따옴표 없이 작성한다.

---

## 2. 컬럼 이름을 지정하지 않는 INSERT

컬럼 이름을 생략하면 테이블에 정의된 **모든 컬럼에 순서대로 값을 입력**해야 한다.

```sql
INSERT INTO departments VALUES (
    500, '인공지능학과', '공학관', '051-123-4567',
    'ai@myschool.ac.kr', 2001, 'http://ai.myschool.ac.kr'
);
```

- 모든 컬럼에 대한 값을 입력해야 한다.
- 값의 순서는 **테이블 컬럼 순서와 동일**해야 한다.
- 테이블 구조가 변경되면 오류가 발생하기 쉽다.

테이블 구조 확인:

```sql
DESC departments;
```

---

## 3. 컬럼 이름을 지정하는 INSERT

입력할 컬럼을 직접 지정할 수 있다.

```sql
INSERT INTO departments (
    id, dname, loc, phone, email, established, homepage
)
VALUES (
    501, '사회복지학과', '인문관', '051-432-2233',
    'social@myschool.ac.kr', 2002, 'http://social.myschool.ac.kr'
);
```

- 테이블명과 `VALUES` 사이에 컬럼명을 작성한다.
- 컬럼명은 쉼표(`,`)로 구분한다.
- 컬럼의 나열 순서는 테이블 구조와 달라도 된다.
- 단, **지정한 컬럼과 VALUES의 값은 1:1로 대응**해야 한다.
- 컬럼 이름을 지정하는 방식이 더 안전하다.

# 2. 데이터 무결성

## 2-1. 데이터 무결성이란?

데이터가 **틀리지 않고 논리적으로 올바른 상태를 유지하도록 보장하는 것**이다.

잘못된 데이터가 저장되지 않도록 테이블 생성 시 여러 제약조건을 설정한다.

| 무결성 | 의미 | 대표 제약조건 |
|---|---|---|
| 엔티티 무결성 | 각 행을 유일하게 식별 | `PRIMARY KEY` |
| 도메인 무결성 | 컬럼에 허용되는 값의 범위를 제한 | `NOT NULL`, 데이터 타입 |
| 참조 무결성 | 다른 테이블과의 관계를 올바르게 유지 | `FOREIGN KEY` |

### 엔티티 무결성

각 행(Row)을 고유하게 식별할 수 있어야 한다.

대표 제약조건:

```sql
PRIMARY KEY
```

예를 들어 학생번호가 기본키라면:

- 같은 학생번호를 중복 저장할 수 없다.
- 학생번호를 `NULL`로 저장할 수 없다.

### 도메인 무결성

컬럼에 들어갈 수 있는 값의 범위를 제한한다.

대표 제약조건:

- `NOT NULL`
- 데이터 타입

예:

- 나이 → 숫자만 허용
- 이름 → NULL 허용하지 않음

### 참조 무결성

다른 테이블에 존재하는 값을 참조하도록 제한한다.

대표 제약조건:

```sql
FOREIGN KEY
```

예: 학생 테이블의 `학과 ID`는 학과 테이블에 실제로 존재하는 `학과 ID`를 참조해야 한다.

# 3. PRIMARY KEY

## 3-1. 기본키(Primary Key)

기본키는 테이블의 각 행을 **유일하게 식별하기 위한 컬럼**이다.

### 특징

- 값이 중복될 수 없다.
- `NULL`을 저장할 수 없다.
- 하나 이상의 컬럼으로 구성할 수 있다.
- 테이블마다 하나의 PRIMARY KEY만 존재한다.

테이블 구조 확인:

```sql
DESC departments;
```

결과에서 다음과 같이 표시된다.

```text
Null : NO
Key  : PRI
```

- `NO` → NULL 허용 안 함
- `PRI` → PRIMARY KEY

> **PRIMARY KEY = 중복 불가 + NULL 불가**

---

## 3-2. PRIMARY KEY 중복

이미 존재하는 기본키 값을 다시 입력하면 오류가 발생한다.

```sql
INSERT INTO departments (
    id, dname, loc, phone, email, established, homepage
)
VALUES (
    501, '사회복지학과', '인문관', '051-432-2233',
    'social@myschool.ac.kr', 2002, 'http://social.myschool.ac.kr'
);
```

`id = 501`이 이미 존재하는 경우:

```text
ERROR 1062 (23000): Duplicate entry '501' for key 'PRIMARY'
```

# 4. AUTO_INCREMENT

## 4-1. 자동 증가 일련번호

`AUTO_INCREMENT`는 새로운 데이터가 입력될 때 숫자를 자동으로 증가시켜 저장한다.

`DESC`로 확인하면:

```text
Field : id
Key   : PRI
Extra : auto_increment
```

기존 마지막 `id`가 `501`이라면 새로운 데이터의 `id`는 자동으로 `502`가 된다.

---

## 4-2. AUTO_INCREMENT 컬럼에 NULL 입력

자동 증가 컬럼 위치에 `NULL`을 입력할 수 있다.

```sql
INSERT INTO departments VALUES (
    NULL, '심리학과', '인문관', '051-336-7788',
    'psyc@myschool.ac.kr', 2000, 'http://psyc.myschool.ac.kr'
);
```

`id`가 `AUTO_INCREMENT`이므로 `NULL`이 그대로 저장되는 것이 아니라 **다음 일련번호가 자동으로 생성**된다.

---

## 4-3. AUTO_INCREMENT 컬럼 생략

컬럼명을 지정하는 경우 자동 증가 컬럼 자체를 생략할 수 있다.

```sql
INSERT INTO departments (
    dname, loc, phone, email, established, homepage
)
VALUES (
    '체육학과', '체육관', '051-434-3345',
    'phy@myschool.ac.kr', 2004, 'http://phy.myschool.ac.kr'
);
```

`id`를 입력하지 않아도 자동으로 다음 번호가 생성된다.

### 정리

```sql
-- 방법 1 : NULL 입력
INSERT INTO departments
VALUES (NULL, ...);

-- 방법 2 : AUTO_INCREMENT 컬럼 생략
INSERT INTO departments (dname, loc, ...)
VALUES (...);
```

# 5. NULL 데이터

## 5-1. NULL이란?

`NULL`은 **값이 존재하지 않는 상태**를 의미한다.

- `NULL` ≠ `0`
- `NULL` ≠ `''` (빈 문자열)
- NULL은 값 자체가 없는 상태이다.

---

## 5-2. NULL 직접 저장

NULL을 허용하는 컬럼에는 `NULL`을 직접 입력할 수 있다.

```sql
INSERT INTO departments (
    dname, loc, phone, email, established, homepage
)
VALUES (
    '성악과', '음악관', '051-435-3535',
    'music@myschool.ac.kr', 2004, NULL
);
```

결과:

```text
homepage = NULL
```

`NULL`은 대소문자를 구분하지 않는다.

---

## 5-3. 컬럼을 생략하여 NULL 저장

NULL을 허용하는 컬럼은 INSERT에서 생략할 수도 있다.

```sql
INSERT INTO departments (
    dname, loc, phone, email, established
)
VALUES (
    '정보통신학과', '공학관', '051-436-3636',
    'ic@myschool.ac.kr', 2004
);
```

`homepage`를 입력하지 않았으므로 `NULL`이 저장된다.

단, 해당 컬럼이 NULL을 허용해야 한다.

# 6. NOT NULL

## 6-1. NOT NULL 제약조건

`NOT NULL`은 해당 컬럼에 **반드시 값이 존재해야 한다**는 의미이다.

```sql
DESC departments;
```

결과에서:

```text
Null : NO
```

→ NULL 허용 안 함

```text
Null : YES
```

→ NULL 허용

---

## 6-2. NOT NULL 컬럼에 NULL 저장

`NOT NULL` 컬럼에는 `NULL`을 입력할 수 없다.

예를 들어 `phone`이 `NOT NULL`인 경우:

```sql
INSERT INTO departments (
    dname, loc, phone, email, established, homepage
)
VALUES (
    '고고학과', '인문관', NULL,
    'music@myschool.ac.kr', 2005, NULL
);
```

→ 오류 발생

NOT NULL 컬럼을 아예 생략해도 기본값이 없다면 오류가 발생한다.

```sql
INSERT INTO departments (
    dname, loc, email, established
)
VALUES (
    '고고학과', '인문관',
    'music@myschool.ac.kr', 2005
);
```

오류:

```text
ERROR 1364 (HY000): Field 'phone' doesn't have a default value
```

# 핵심 정리

| 개념 | 핵심 |
|---|---|
| `INSERT INTO` | 새로운 데이터 입력 |
| `VALUES` | 저장할 값 지정 |
| 컬럼명 생략 | 모든 컬럼 값을 테이블 순서대로 입력 |
| 컬럼명 지정 | 필요한 컬럼만 선택해서 입력 가능 |
| `PRIMARY KEY` | 중복 불가 + NULL 불가 |
| `AUTO_INCREMENT` | 숫자값 자동 증가 |
| `NULL` | 값이 존재하지 않는 상태 |
| `NOT NULL` | 반드시 값을 입력해야 함 |
| `FOREIGN KEY` | 다른 테이블의 값을 참조 |

## ⭐ 꼭 기억할 것

### PRIMARY KEY
- 중복 불가
- NULL 불가

### AUTO_INCREMENT
- 값을 생략하면 번호 자동 생성
- `NULL`을 넣어도 번호 자동 생성

### NULL
- 값이 없는 상태
- `0`이나 빈 문자열과 다름

### NOT NULL
- 값 입력 필수
- NULL 입력 불가
- 기본값이 없다면 컬럼 생략도 불가
